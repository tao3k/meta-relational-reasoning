#+title: RFC 0027: Typed Gerbil Runtime Status Observability
#+status: accepted
#+options: toc:2
#+property: header-args :eval never-export :exports code

* Decision

The MRR native boundary preserves =gerbil-scheme-sys= status semantics instead
of reducing failures to an unexplained integer.  =NativeRuntimeStatus= carries
the exact numeric ABI code and, when the upstream crate recognizes it, its
=GerbilStatus= meaning.  Unknown future codes remain observable and fail
closed; MRR does not define a second status table.

#+begin_src mermaid
flowchart LR
  A[Gerbil AOT ABI] --> C[exact status code]
  C --> U[upstream GerbilStatus decoding]
  U --> M[NativeRuntimeStatus]
  C --> M
  M --> E[typed MRR error]
#+end_src

* Contract

The raw code is never discarded, known meanings are formatted beside the
code, and every native grammar, parse-artifact, and driver failure propagates
the same status owner.  No retry, fallback process, or inferred runtime state
is introduced by this observability layer.

* Evidence

Unit tests cover a recognized upstream code and an unknown code.  Native AOT
tests exercise propagation through the existing fixed-width ABI after a fresh
=mrr-gerbil build=.

* Build observations and source-handoff ownership

The module closure belongs to root =build.ss= and its existing PackageSpec.
=crates/mrr-gerbil/build.rs= delegates to =mrr-gerbil-build=; the latter uses
the pinned gerbil-scheme-rust integration project. It is not an MRR Data SDK.
Compiler selection, optimization, ABI and subprocess diagnostic framing belong
to gerbil-scheme-rust. Consumer Python must not construct compiler commands.

The PackageSpec emits actual entry and return observations regardless of detailed
verbosity. Return is not interpreter quiescence; successful child termination
and complete archive identity are still necessary. Cargo phase summaries remain
visible at verbosity zero, while per-module diagnostics retain their existing
verbosity filter. Failed observations always use the error observation channel.
There is no timer heartbeat or timeout extension.

MRR's workspace explicitly selects =mrr-frontends/embedded-runtime= rather than
inheriting it from frontend defaults. This preserves the original source parsing
semantics: =mrr-property-source= depends on those frontends even without its
optional =native-inference= feature. Thus MRR Data =source-handoff= can require
the embedded Scheme grammar, while its base storage layer does not. Turning
that feature off merely to make CI green would change the application contract.

The current dependency pin still names an earlier upstream build package.
Renaming the MRR-owned adapter does not rename or replace that pinned dependency.
A separately verified upstream framing fix is not automatically present in this
pinned consumer; adoption requires a later explicitly authorized dependency change.

* Embedded tooling ownership and inherited Cargo output

The required public build/test API belongs in gerbil-scheme-rust and invokes
the actual Gerbil Scheme procedures through C ABI. The existing minimal runtime
image does not provide the complete compiler/gxtest closure. Tokio process I/O
is bootstrap hardening, not an embedded tooling implementation. MRR's build.ss
remains unchanged; no Cargo loop, eval endpoint or second build DSL is added.
The upstream embedded-tooling contract records admission, affine VM ownership,
root lifetime, cancellation observation and complete build/test evidence.

Cargo must run as the native root. In the audited standard gxpkg implementation,
=env= starts native children with inherited descriptors. Actual Darwin probes
show nonblocking stdout/stderr after that entry. A slow native-reader fixture
reproduces truncated Cargo metadata despite zero exit status, and a nonzero
verbose-build refusal. Native Cargo preserves all 1,508,947 metadata bytes across
12 host workers and leaves no owned process groups. The complete paired check
including verbose refusal/recovery passes within the unchanged 45-second bound.

CI therefore invokes Cargo/Python and existing legacy qualification scripts
without an outer Gerbil interpreter. The job declares its standard local
=GERBIL_PATH= explicitly; this is package location, not compiler/linker policy.
Existing bootstrap package
actions remain standard Gerbil commands pending the admitted C ABI capability.
Isolated Rust probes exercise dependency installation and safe package recovery
through the existing pinned API; these probes remain temporary evidence rather
than a new MRR driver. Rust build.rs already delegates artifact construction to
the pinned upstream builder. This does not claim that dependency has the new C ABI
tooling API. The optional backpressure test retains a native negative control;
neither successful status nor short output is accepted as complete evidence.

Local full-entry failures remain separate: missing Parser output, incomplete
dependency products after a mixed compiler environment, unsafe all-package clean
ordering and a 900-second wall refusal incorrectly labeled as five-second
backpressure. The supervisor's reporting correction preserves every deadline
and only distinguishes an expired total budget from a live forwarding refusal.
Only standard package clean/build
actions recover generated products; no uninstall or source-pin edit is used.
