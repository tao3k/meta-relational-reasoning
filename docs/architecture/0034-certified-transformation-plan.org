=TransformationDefinition= requires schema version, profile, complete
source/target semantic type identities, forward artifact/reference,
extractor artifact/reference, parameter contract, condition expressions,
capability requirements, semantic evidence statement/reference, and encoding
contract/reference. It describes immutable content. =TransformationId= is
derived from that canonical content. Current availability belongs to a
separate admission state. Retain stable public names separately from content
versions; changing the implementation produces a new content identity.

=TransformationAdmission= binds the definition digest, exact source-authority
revision set, MRR generation/snapshot digest, certificate-check receipt,
policy/verifier version, scope, and selected temporal coordinates. Physical
blob CIDs, code commits, MRR semantic IDs, and Lean theorem names remain
distinct coordinates checked individually by the receipt.

=TransformationPlanCandidate= carries request/context/input digests, ordered
edge instances including parameters and adapters, selected source snapshot,
target solver/reference, and budgets. =TransformationPlanAdmission= also
carries per-edge obligation receipts, ordered dependency digest, composite
statement, plan digest, and completion status. External callers cannot
construct admitted values directly; decoded values are revalidated. Canonical
encoding specifies field order, optional tags, set ordering, duplicate
rejection, string normalization, and size bounds.

Source selection must atomically identify revisions of all participating
sources. A generation alone is insufficient. Mathematical definitions and
theorems may be reused across time; current availability, capabilities, and
authorization require fresh admission. Declared temporal policy selects
valid-time and knowledge-time. Timestamps do not establish causality, and
polling does not establish completeness. See [[file:0013-generation-revision-semantics.org][RFC 0013]].

* Minimal complete Lean contract
:PROPERTIES:
:CUSTOM_ID: transformation-proof
:END:

The first profile states that a correct target result for a valid input can
be soundly extracted into a source result. Forward is total and the extractor
is indexed by the original instance. Additional parameters can be packaged
into Input/Context. This profile establishes witness soundness; decision
reductions additionally need yes/no equivalence, optimization profiles need
objective/approximation laws, and partial or effectful transformations need
failure, termination, or trace contracts. Inverse behavior and runtime
complexity require explicit additional laws.

The following standalone contract is a candidate for the LeanPOO slice.
Prove semantic composition first, then attach Certified factories/ContextSlot
evidence reuse around it. =conjoin= combines claims about one factory family;
cross-endpoint transformation composition requires the contract below.
Its four theorems must pass kernel checking with no added axioms. Concrete
edges must supply soundness proofs; replacing the task specification with
=True= does not satisfy that obligation.

The same example compiled with LeanPOO's pinned Lean 4.34.0 and MRR's pinned
Lean 4.31.0. All four =#print axioms= reports showed no axiom dependencies.
Future library dependencies and artifacts require version-specific checking
before crossing this bridge.

#+name: transformation-contract-kernel
#+begin_src lean
namespace TransformationAudit

structure Problem where
  Input : Type
  Result : Input -> Type
  Valid : Input -> Prop
  Correct : (a : Input) -> Result a -> Prop

structure CertifiedTransformation (A B : Problem) where
  forward : A.Input -> B.Input
  preserves : forall a, A.Valid a -> B.Valid (forward a)
  extract : (a : A.Input) -> B.Result (forward a) -> A.Result a
  sound : forall a, A.Valid a -> forall r, B.Correct (forward a) r ->
    A.Correct a (extract a r)

def identity (A : Problem) : CertifiedTransformation A A where
  forward := id
  preserves := fun _ valid => valid
  extract := fun _ r => r
  sound := fun _ _ _ correct => correct

def compose {A B C : Problem} (f : CertifiedTransformation A B)
    (g : CertifiedTransformation B C) : CertifiedTransformation A C where
  forward := fun a => g.forward (f.forward a)
  preserves := fun a valid => g.preserves _ (f.preserves a valid)
  extract := fun a r => f.extract a (g.extract (f.forward a) r)
  sound := fun a valid r correct =>
    f.sound a valid _ (g.sound _ (f.preserves a valid) r correct)

theorem compose_sound {A B C : Problem} (f : CertifiedTransformation A B)
    (g : CertifiedTransformation B C) (a : A.Input) (valid : A.Valid a)
    (r : C.Result ((compose f g).forward a))
    (correct : C.Correct ((compose f g).forward a) r) :
    A.Correct a ((compose f g).extract a r) :=
  (compose f g).sound a valid r correct

theorem compose_forward_assoc {A B C D : Problem}
    (f : CertifiedTransformation A B) (g : CertifiedTransformation B C)
    (h : CertifiedTransformation C D) (a : A.Input) :
    (compose (compose f g) h).forward a =
      (compose f (compose g h)).forward a := rfl

theorem compose_extract_assoc {A B C D : Problem}
    (f : CertifiedTransformation A B) (g : CertifiedTransformation B C)
    (h : CertifiedTransformation C D) (a : A.Input)
    (r : D.Result (h.forward (g.forward (f.forward a)))) :
    (compose (compose f g) h).extract a r =
      (compose f (compose g h)).extract a r := rfl

theorem identity_extract {A : Problem} (a : A.Input) (r : A.Result a) :
    (identity A).extract a r = r := rfl

#print axioms compose_sound
#print axioms compose_forward_assoc
#print axioms compose_extract_assoc
#print axioms identity_extract
end TransformationAudit
#+end_src

* Certificate bridge and trust boundary
:PROPERTIES:
:CUSTOM_ID: transformation-bridge
:END:

MRR must validate more than a deserialized theorem name. The first bridge
uses a fixed checker and auditable build artifacts: exact Lean toolchain,
library/dependency manifest, module artifact digest, complete statement
digest, declared assumptions, and implementation/codec digests. The checker
returns a completed check receipt. Admission policy determines allowed
axioms and environments. Source authority is checked independently of the
axiom report.

A slice compiling and executing pure Lean forward/extract definitions can
bind the same definitions and artifacts. An external Rust, Scheme, or Python
function sharing a Lean definition's name still requires implementation
refinement. Until proved, identify its evidence as tested or reference
correspondence. A digest binds content; semantic correctness and issuer
authentication require separate checks.

The protocol distinguishes Candidate, CheckedSemanticEvidence,
AdmittedDefinition, AdmittedPlan, and ExecutionReceipt. A correct edge
certificate leaves runtime authorization and execution success as separate
obligations. Execution receipts bind concrete input/output, plan, artifact,
context/source snapshot, output codec, and correctness witness. Source or
current-revision changes trigger revalidation. Partial results and unknown
execution outcomes cannot enter a completed-result cache.

* ASCENT projection and path validation
:PROPERTIES:
:CUSTOM_ID: transformation-ascent
:END:

MRR admits inputs before projecting bounded scalar-ID tables:
edge(instance,src,dst), admitted(instance,cut), requires(instance,requirement),
available(requirement,context,cut), and terminal-solver(target,solver,cut).
The MRR adapter binds the schema and scalar-ID codec. ASCENT receipts bind
query/program, codec, row digest, source snapshot, budget, and completion.

=reachable= establishes a graph consequence. Under an open-world contract,
absence of a capability cannot establish its unavailability. Admitted rules
or checkers establish dynamic premises. If a capability requires execution,
planning retains an obligation and publishes the capability only after
execution succeeds. Consumable resources accumulate step by step; runtime
effects require their own execution model.

Recursive reachability must avoid unbounded path-list materialization,
especially in cyclic graphs. ASCENT returns bounded edge supports or candidate
endpoints. MRR extracts a length-bounded ordered witness and validates each
edge's connectivity, version, context, parameters, and evidence. Alternative
enumeration has explicit count/depth/work budgets. Exhaustive enumeration
claims require a finite path domain. Empty paths require equal endpoints and
the identity profile. Before dereferencing evidence, confirm every external
reference belongs to the same admitted source selection.

Deletion or revocation affects dependents. MRR lineage computes reverse
impact and invalidates old admissions. Publish a candidate source selection
atomically after its solve completes; retain the previous completed result
with STALE freshness. What-if uses a forked selection and independent receipt.
WHY-NOT projects to FALSE only with complete finite closed-world coverage of
every rule and source. Budget stops are INCOMPLETE, missing coverage is
UNKNOWN, and incompatible authorities produce CONFLICT. Reuse the state
projections in [[file:0023-mrr-truth-and-incompleteness.org][RFC 0023]].

ASCENT retains ownership of native encoding, decoders, index completeness,
pivot/delta selection, mutation, and asynchronous trace refinement. These
bridge obligations complement the partial PositiveConsequence theorems;
the native runtime needs its own complete refinement evidence.

* Concrete profiles, resource laws and authenticated publication

[[file:../../crates/meta-relational-reasoning/src/transformation_profiles.rs][Concrete finite profile factories]] build distinct typed adapters:

- =KernelCheckedDecisionReduction= uses Boolean decision specifications and
  identity Boolean extraction. The exact finite transport checks agreement on
  positive and negative decisions.
- =KernelCheckedOptimizationReduction= lowers feasible answers and natural costs
  to every minimum-cost answer, retaining ties. Independent Lean obligations
  compare every lowered row with the original feasibility/cost predicate before
  issuing the kernel certificate. A feasible but nonoptimal extraction fails.
- =KernelCheckedPartialTransformation= restricts to explicitly successful original
  inputs. =source_instance= supplies the required compact-domain adapter; omitted
  inputs return =Unknown=. The domain map participates in endpoint identity.

The canonical V1 carrier remains exact finite witness transport. Richer profile
properties are supplied by these checked factories and their endpoint
specifications, rather than an unchecked wire enum. The source owner still owns
the meaning of the supplied domain, feasibility, decision and cost tables.

[[file:../../proofs/MRRProof/TransformationProfiles.lean][Generic profile laws]] prove decision equivalence, successful partial
composition and optimality transport. [[file:../../proofs/MRRProof/TransformationResources.lean][Measured resource and effect laws]] prove
composition of bounds on actual implementation size/cost functions and of actual
state-indexed authorized forward/extractor traces. These public interfaces are
also in [[https://github.com/tao3k/lean-poo/pull/9][LeanPOO PR #9]]. Native consumers must instantiate their premises; a raw
resource declaration supplies no CPU complexity proof.

[[file:../../crates/meta-relational-reasoning/src/transformation_authority.rs][Authenticated finite publication]] accepts a bounded canonical CBOR signed grant
from a configured Ed25519 issuer. The grant binds the exact snapshot/request/
context/scope/time coordinates, complete catalog, pinned kernel, checker/runtime policy, authentication/execution/publication source and dependency lock, nonce,
validity interval, per-operation capabilities, logical runtime-call budget and
encoded-value byte budget. The adapter uses =ed25519-dalek= 2.2.0
[[https://docs.rs/ed25519-dalek/2.2.0/ed25519_dalek/struct.VerifyingKey.html#method.verify_strict][strict signature verification]] and rejects weak issuer keys. Authentication is
additional to the actual semantic checker. Grant issuance/signing belongs to the
source owner; this module stores no signing key and admits no foreign code.

For a plan with =n= transport steps, the fixed runtime invokes =n= forwards,
one solver, =n= extractors, and =n + 1= independent answer checks. Admission
requires the signed operation limit to cover =3n + 2=. This counts logical
runtime calls, not machine instructions or checker CPU time. Values are checked
against the signed encoded-byte limit at actual runtime boundaries; affine
resource composition uses checked =u64= arithmetic and rejects overflow.

The grant ledger has an exclusive OS lock, canonical bounded state, issuer pin,
monotone revocation epoch, atomic replacement and directory fsync. Capacity or epoch exhaustion quarantines the authority and persists that state; an idempotent revocation retry repeats the write before acknowledging success. A pending
revocation file prevents reopening after an uncertain interrupted write. Failed
persistence never acknowledges durable revocation; the live owner remains
revoked. Deleting or rolling back owner-controlled ledger files is outside its
trust model. =revoke_grant= records nonce revocation before invalidating a result;
policy and nonce support identities enter the durable reverse index. If the
result write fails, the grant remains revoked.

Each admission and actual forward/solve/extract checks a fresh grant lease.
Final publication holds the ledger read guard and native source guard while
writing the result. Stored freshness checks expiry/revocation again. If expiry or a directory-sync failure follows atomic replacement, publication
returns =PublicationUncertain=, keeps the previous known in-memory result and
never acknowledges the new bytes as fresh. Historical
answers survive denied operations, exhausted budgets, expiry and revocation;
they are never upgraded by reopening serialized records.

* Physical-provider signed grant boundary

=AuthenticatedTransformationGrant= authenticates an Ed25519 grant against a
separately configured ledger issuer and the caller's exact expected binding and

* Byte identity transport source refinement

The production =transport_transformation_bytes= helper clones an arbitrary byte
slice using Rust =to_vec=. Charon/Aeneas extracts that exact helper alongside the

* Physical durable publication and restart recovery

=TransformationResultStore::execute_and_publish_async= executes the selected
physical runtime and independent answer checker before its synchronous owner
publication lease. The existing process lock, bounded canonical archive,
atomic replacement and file/directory fsync implement persistence.

The support cut includes provider authority supports, runtime identity, admitted
edges, dependencies, requirements, source revisions, solver and binding.
Reopening exposes historical data only. =replay_async= repeats admission,
physical execution and answer checking and compares the exact archived support,
plan, execution and answer before recovering freshness. Durable invalidation
survives restart. Cancellation releases no fresh record; loss of authorization
after replacement reports =PublicationUncertain=.

The publication port is an owner trust boundary, separate from transformation
certification. Physical integration must supply a live lease tracking both

test verifier or a signed source grant into a production correctness certificate.
