* Status

Accepted MVP slice.

* Decision

=mrr-frontends= is a peripheral adapter crate.  Callers select =Gql= or
=Cypher= explicitly; both adapters consume the Gerbil-projected Rowan syntax
surface, lower the supported AST slice directly, and admit only shared
=MetaQueryIr=.  They do not route through =gql-ir= or =gql-sema= and do not
expose either contract.

The parity slice is deliberately bounded to one =MATCH= graph pattern,
node/relationship type labels, direction, bounded path quantifiers, property
constraints and access, =WHERE= expressions, =RETURN= projection, ordering,
and limit.  Unsupported mutation, optional matching, union, offset, case,
subscript, and unowned operators fail before IR admission.

Stable entity/relation type identities derive from language-neutral label
content.  Query and operator identities derive from the span-free semantic AST
projection, so source filename, whitespace, and selected frontend dialect do
not change the admitted relational intent.

* Executable equality

The focused acceptance query contains typed nodes, an outgoing typed relation,
property access in a predicate, and a projection.  Both explicit frontend
instances must return equal normalized IR and byte-identical versioned canonical
encoding.

= RFC 0007: Frontend Parity

For the admitted common surface $S$ and semantic normalization $N$,

$ N("lower"_"GQL"(s)) = N("lower"_"Cypher"(s)) $

for every $s in S$.  Parser diagnostics or an unsupported construct produces
no partial =MetaQueryIR= value.
