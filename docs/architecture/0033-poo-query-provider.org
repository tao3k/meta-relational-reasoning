* Native semantic owner
:PROPERTIES:
:CUSTOM_ID: mrr-result-native-owner
:END:

MRR's =QueryResultAdmissionReceipt= is produced after typed admission of a
physical candidate against one =CatalogBoundQuery=.  It retains the binding's
query digest, generation, relation-catalog digest, entity-catalog digest and
snapshot digest, plus row count and an MRR-owned digest over ordered columns
and rows.  MRR result admission does not assert execution authenticity,
completeness or downstream causality.  Its implementation and proof scope
remain owned by the MRR repository.

The MRR-owned POO =MrrResultAdmissionProjection= records those fields with canonical
lowercase SHA-256 text encodings and a separate POO Query source hash.  The
projection digest covers all fields.  It is a *declared representation* of
native metadata: this Scheme constructor cannot prove that an MRR runtime
emitted it or that its bound query denotes the same semantics as the POO
Query.  No native Rust-to-Scheme exporter or attested crosswalk is wired yet.

* Temporal handoff
:PROPERTIES:
:CUSTOM_ID: mrr-result-temporal-handoff
:END:

=mrr-projected-candidate-receipt= first replays the ordinary GQL
Query/ElementSpace/Provider receipt binding.  It then replays the MRR
projection and checks the separately declared Temporal cut and host generation,
provider, result digest and row count. The projection v2 digest binds both native
and Temporal identities. Replay also compares the declared Query source digest
against the reconstructed source, rejecting relabeling under an unchanged
projection digest. A snapshot may differ from a causal cut, and a native
GenerationId is never coerced to the Temporal generation integer.  Its output uses the distinct
=mrr.query-result-admission.v1:sha256:= digest label and forces
=complete?= =#f= even when a caller's SourceQueryReceipt says complete.  A
typed MRR result-admission receipt does not by itself establish a complete
source inventory or exhaustive query answer, so an exchange remains
=pending= even if a caller supplies a =valid= CandidateCheck.  The POO Flow
scalar-row checker rejects the MRR digest label;
transcoding MRR's ordered typed rows into an unordered scalar set would lose
semantics.

* Native Scheme result transport v1

The facade exports =mrr.query-result-transport.v1= as an inert Scheme datum
under a caller-owned byte limit. JSON and unapproved v2 records are rejected directly;
there is no compatibility decoder. The existing Rust export/verify functions
retain their names. Consumers update immutable source pins while retaining
protocol version 1. Context query-selection storage records remain version 1;
an old stored selection must be regenerated from its original admitted inputs.
=AgenticAiContextQuerySelectionRecord::to_scheme_bytes/from_scheme_bytes=
use this bounded native codec for the complete storage envelope. Decoding is
inert and does not bypass original Source/result/selection re-admission. JSON
and v2 envelopes are rejected; the caller supplies an explicit byte ceiling.

The grammar is the ABI v1 subset =null=, =#t=, =#f=, decimal integers, quoted
UTF-8 strings, =(list ...)= and =(object ("field" value) ...)=. Escapes are
only quote, backslash, n, r and t; other control characters, reader extensions,
comments, duplicate fields, trailing data and unknown envelope fields fail.
Depth is capped at 64; datum nodes are bounded by the caller-owned byte ceiling. MRR Float and Decimal values
remain their original typed canonical strings; the codec does not round them.

The typed Serde projection preserves all result variants, schemas, ordered
columns, rows, duplicates and original receipt identities. Encoding borrows
rows, performs a nonallocating output preflight, then re-admits and writes to a
bounded sink. The decoder builds a bounded inert data tree and deserializes the
owner types; =ciborium::Value= is an internal typed tree, not a CBOR transport.
The existing admission digest remains =mrr.query-result-admission.v1= over the
original canonical CBOR semantic values. Transport version is not semantic
identity. Resource limits do not change a successful candidate's digest.

The receiver independently supplies the authentic =CatalogBoundQuery=. Native
verification checks all five original binding identities, re-runs row/type and
budget admission, and compares count and digest. A transport is not proof of
execution, completeness, source authentication, current applicability or effect
authorization. A zero-row result remains a valid typed result and does not
establish closed-world absence. Graph nodes, relations and nested result values
are not reduced to POO's narrower event/position observation profile.

* Integration gates and ownership

POO PR #34 at =aa04d5738e4cacb81f3d043842ca47144ccb39f4= already consumes
MRR candidate/receipt owner types in-process and calls Scheme semantic ABI v1.
Its narrow event/position bridge uses a typed fixture. The MRR code here supplies
the owner-side cross-process representation; it does not import POO's runtime
or become a second Temporal interpreter. The Scheme projection is still declared
metadata and always emits an incomplete candidate exchange. Parsing transport
or constructing a projection cannot authenticate the native producer.

Before physical G0 acceptance, MRR Data must export this original transport from
its restored-root query result and update its MRR pin. POO must verify the
original source compilation, native query, catalog, source revision vector and
separate cut/clock correspondence. Result integrity and physical execution
receipts remain distinct. Negative acceptance must change root, source, query,
catalog, row and cut independently.

The following bidirectional gates remain separate from G0: POO conclusion/proof
projection with original support identities; late correction and current-state
fences; alternative supports and bounded absence; recursive dependency handling;
IFC and publication authority. MRR lineage impact is a reevaluation frontier,
not proof that every reached conclusion is false. Reimported conclusions cannot
become independent observations. Preserve immutable history and check current
applicability at consumption. No full Temporal/MRR lifecycle closure is claimed.
