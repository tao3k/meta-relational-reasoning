* Responsibilities

| Owner | Responsibility |
|-------+----------------|
| POO Flow | Scheme Temporal/causal/IFC engines, functional Library, shared C ABI, Python Library |
| MRR | Rust owner-thread lifecycle, bounded requests, typed evidence/source adapters, publication orchestration |
| MRR Data | Physical queries/content, native backend transactions, authority fences, durable head/delivery/recovery |

MRR =runtime/= loads the exact POO-produced native Library. It does not port the
Scheme solver into Rust. =mrr_publication= sends an original conditional content
commit through Data's configured port, with native validation inside the held
transaction. There is no MRR-owned database implementation or new persistence
engine. Native admission, source currentness and authorized disclosure remain
separate gates.

* Migration

Runtime source, tests, release-pair locks and original physical roundtrip producer
move from POO into this repository. The crate is =mrr-runtime=; the physical
producer is =mrr-temporal-physical-roundtrip=. No old crate alias is provided.
POO checks out an immutable MRR owner commit to exercise its current Library;
MRR CI compiles the runtime and rejects release-pair drift. Actual native
acceptance is separate from compilation.

The runtime has its own Cargo workspace and lock, rather than implicitly
combining the enclosing development kernel with Data's already qualified Git
kernel. MRR producer ffde2798 and Data 513d6781 remain the actual tested pair.
The owner checkout revision identifies the runtime implementation; the producer
revision identifies the typed semantic contract. Updating that pair is an
explicit multi-repository qualification step, not a consequence of moving files.

* Evidence boundaries

Scheme datum/ABI version remains v1 and Gerbil remains v0.19. Python model IO
and POO Library tests stay under POO's existing packages. Rust assertions belong
to MRR or Data. Raw logs and compiler outputs remain local/CI artifacts.

Moving ownership does not establish source issuer authenticity, external effect
exactly-once execution, universal Quint/native refinement or production clock
security. These require their own executable acceptance.

* Durable grant retirement acceptance

The native physical producer now has an independent publication home for grant
controls. The original proof and physical root remain eligible while Data alone
changes the grant. It rejects a previously captured generation after an active
commitment is rotated away and restored to identical bytes (ABA). Retirement
then rejects fresh use, refuses resurrection of the same authority identity,
and remains mandatory when a differently named grant is enrolled. Each refusal
occurs before the fresh clock/native validator; no revision-two delivery exists.

After real provider shutdown/reopen and a genuine native source correction,
that grant remains retired. The original acknowledged delivery and exact old
operation replay survive; a stale native proof does not trigger revalidation,
a new clock or a new effect. This is historical recovery, not fresh authority.
Required markers are =NATIVE-TO-DATA-GRANT-ABA-RETIREMENT-ALIAS-REFUSED= and
=NATIVE-TO-DATA-RETIRED-GRANT-HISTORICAL-REPLAY-RECOVERED=.

The full physical gate and strict Clippy pass on the unchanged official native
artifact, with five-second idle and 45-second execution limits. The MRR CI
ASCII-source failure is repaired with equivalent Rust Unicode escapes; both
the Unicode datum roundtrip and the exact failing repository policy test pass.
The repository policy remains enforced. No semantic producer pin, provider
implementation, Scheme/ABI version or external effect path is changed.
