#+title: POO Flow Temporal in the MRR Production Runtime
#+startup: overview

* Decision and implementation boundary

MRR is the Rust production runtime for the POO Flow contracts it implements.
POO Flow owns the public POO objects and functional Temporal semantics. MRR
executes those semantics through an embedded, ahead-of-time compiled Scheme
library and supplies typed admission, concurrency and durable runtime effects.
The Scheme ASCENT library owns finite relational evaluation. Rust ASCENT is
removed from the target runtime, including Search factor inference.

The inference adapter now composes ASCENT's maintained native POO table
expression in =scheme/reasoning/finite.ss=. =mrr-deduction= and =mrr-search=
retain typed admission and independent witness checks; both execute the native
Scheme candidate on the =mrr-gerbil= owner thread. Rust ASCENT execution and
the former =mrr-ascent= package are removed. Full Temporal generation, correction,
recovery and effect publication remain separate production obligations.
The bounded read-only physical roundtrip qualifies only its exercised path.

This decision supersedes the runtime restrictions in RFC 0001 and RFC 0020
that confine Gerbil to projection and permit Rust ASCENT as the evaluator.
The restrictions on frontend parsing and language-neutral core dependencies
remain applicable. Embedding compiled Scheme evaluation does not permit
evaluating source text supplied by a caller or model.

Rust preserves identities and checks receipts; Scheme remains the executable
owner of the POO algorithms. Reimplementing Temporal or finite inference in
Rust creates a second semantic engine and does not satisfy this composition.
MRR Data remains a physical adapter: it does not decide Temporal authority.

* MRR to MRR Data execution boundary

MRR dispatches an admitted, snapshot-bound operation to MRR Data. MRR Data
owns the physical Backend and storage/transfer Protocol implementations;
backend choice, credentials, retry and transfer behavior stay behind that
boundary. MRR requests capabilities and retains semantic authority. It does
not embed DataFusion, GraphAr or S3 implementations in its Scheme adaptation.

The =meta_relational_reasoning::PropertyQueryBackend= contract dispatches
through =CatalogBoundQuery::execute_with=. MRR retains backend-owned physical
evidence alongside its own result admission. The higher MRR
=BoundPropertySourceQuery= delegates to this port while retaining the original
parser receipt. MRR Data depends only on the facade's contracts with default
features disabled; its ordinary Backend build needs neither a parser nor a
Scheme SDK. The MRR production facade enables =native-inference= by default,
which composes the Scheme evaluator without a Rust fallback.

MRR Data binds the original query to its immutable root and engine profile,
verifies restored content and executes through the selected Backend. Its
physical output is projected through =project_data_query_output= and checked
by MRR-owned result admission. The existing Scheme result handoff preserves
those identities for the Temporal consumer. Each implementation remains in
its owning repository.

Unavailable transport, permission denial, cancellation, corruption and
confirmed absence retain their distinct protocol meanings. Backend execution
success alone cannot authorize facts, establish source coverage or commit a
Temporal effect. New production dispatch must compose these existing contracts
and propagate their failures rather than create another physical query model.

* One bound operation

A production Temporal request binds the original source identity, admitted
semantic generation, physical root, relation catalog, query binding, event
mapping, valid-time and knowledge-time domain identities, selected cut,
coverage declaration, operation limits, and requested analysis scope.
These are conceptual contract fields, not a newly implemented public API.
Public authoring remains POO-native; transport is bounded inert Scheme data.

The runtime resolves a single immutable source snapshot. It verifies fact
identities and the bijective event mapping before calling Temporal. Logical
positions, observed knowledge positions and valid-time bounds retain their
separate domains; acquisition time cannot substitute for any of them.

Physical query results retain their original MRR receipt and row identities.
Native Temporal and ASCENT receive the admitted snapshot projection. The
returned finite candidate binds the same source, generation, axes, cut,
scope, coverage and input identities. MRR independently checks its structure,
support and binding before attaching admitted facts and lineage. A content
digest cannot authenticate a source or establish complete coverage.

Historical and hypothetical requests remain labelled with their actual
snapshot scope. Missing coverage, unknown coordinates, partial execution or
budget exhaustion cannot become definitive absence or effect authorization.

* Corrections, currentness and publication

An assertion, correction or retraction produces a new admitted generation.
Its immutable history and explicit supersession/retraction links are retained.
The runtime invalidates dependent queries, candidates, lineage projections and
pending publications. Re-query and re-evaluation bind the new generation;
relabeling an old receipt is invalid even if the output rows happen to match.

Read-only analysis can return an explicitly historical result. A publication
must compare the expected generation, cut and relevant policy version with
the current owner state at the commit boundary. That check and the durable
admission/publication intent must occur in one atomic transition. Checking
currentness before computation and committing later without a fence is
insufficient. A concurrent correction or policy revocation blocks the commit.

IFC labels, permitted flow and the exact authorization decision apply to the
data and effect being published. Finite causal evidence cannot supply them.
An external effect requires a durable delivery identity and a recoverable
handoff. A durable outbox can atomically record state and delivery intent;
exactly-once external delivery additionally requires the destination's
deduplication/transaction contract. Recovery cannot infer successful delivery
from a locally committed intent alone.

Recovery verifies stored source roots, generations, bindings and receipts,
reconstructs admitted state, and distinguishes uncommitted, committed and
delivered operations. Retries preserve their operation identity. Replays use
the declared snapshot and clock domains; host wall-clock time is not a replay
input unless the source contract explicitly admits it.

* Native execution and dependency direction

The existing =mrr-gerbil= runtime uses one Gambit owner thread. Production
native calls must preserve that affinity and buffer lifetime discipline.
One process must have one deliberately composed native program closure;
loading the POO ABI and grammar archive independently is not evidence that
two Gambit program initializers can safely coexist.

Language-neutral identity, relation, revision, query and lineage crates remain
independent of Gerbil and ASCENT. A production execution adapter composes
those contracts with the native library. It must not introduce a cycle by
making the native bridge depend on the facade that invokes it. Static rule
declarations are compiled from the Scheme owner; requests contain values,
not dynamically evaluated programs or subprocess commands.

The Rust replacement removes both =ascent!= execution sites and the Cargo
=ascent= dependency. Existing =mrr-ascent= receipt/admission contracts must be
moved to an appropriately named owner or replaced by the admitted native
contract, with all facade consumers migrated. Keeping that crate as a Legacy
alias, replacing inference with a Rust BFS evaluator, or deleting its negative
admission tests does not establish removal. Rust witness reconstruction may
remain an independent receipt check; it cannot become the production solver.

The native archive and architecture dependency allowlists must name the
actual Temporal/ASCENT runtime imports. Build tooling and observability build
modules remain outside the execution closure. Missing native initialization,
unsupported ABI, malformed values, rejected bindings and unavailable runtime
are typed failures; none triggers fallback to the deleted evaluator.

* Executable acceptance obligations

Acceptance requires real native calls for closure, Search factor influence
and Temporal operations, with original typed receipts admitted by MRR. It
also requires rejection of stale generation/cut, substituted source/root,
clock-domain mismatch, incomplete coverage, unsupported inference and
truncated evidence. Rust witness checks preserve deterministic support and
the existing shortest-distance contract without silently changing semantics.

Production currentness requires an exercised correction between computation
and commit, a policy revocation at that boundary, and deterministic conflict
rejection. Recovery requires crash injection before/after durable commit and
delivery acknowledgement, followed by identity-preserving replay and retry.
These obligations are separate from a successful read-only query roundtrip.

Benchmarks and qualification receipts belong to ASP's native Scheme owners.
Cold startup, queueing and steady-state native calls are measured separately.
Five seconds without genuine progress remains failure; queue wait and native
initialization are included where the corresponding operation promises that
deadline. A host timeout alone cannot interrupt or safely reuse an in-flight
Gambit call: bounded native computation or an explicitly isolated worker
lifecycle must establish cancellation and subsequent runtime health.

* Native finite inference and dispatch acceptance slice - 2026-10-04

Removed the Rust =ascent= workspace dependency, =mrr-ascent= package and its
Criterion solver benchmark. =mrr-deduction= retains the original typed closure
contracts and deterministic MRR witness reconstruction; native Scheme supplies
the original finite closure and shortest distances. =mrr-search= delegates its
finite relation/influence evaluation through the same fixed-width ABI.
The maintained ASCENT POO table expression owns closure and shortest-path
semantics. Original observation coordinates and request-local node mappings
remain distinct from MRR fact identities and generations.

The Scheme request eagerly owns input rows before constructing lazy POO slots.
Native start/stage/solve/read/reset execute as one Gambit owner-thread operation.
ABI, coordinate, relation-size, duplicate and distance checks fail closed.
The candidate does not allocate authority or admit lineage. No Rust evaluator
fallback or JSON semantic request is available.
