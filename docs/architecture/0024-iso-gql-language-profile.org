* Status

Accepted inventory and admission boundary. This RFC is not an ISO conformance
claim.

* Decision

Gerbil Parser is the syntax authority for ISO GQL. MRR consumes its versioned
parser descriptor, Grammar IR, parser machine, syntax catalog, and native event
stream. MRR does not maintain another GQL lexer, parser, public AST, semantic
model, catalog model, or language-specific IR in Rust.

=scheme/grammar/gql-profile.ss= is the sole MRR-owned machine-readable inventory
of releases, modules, profiles, feature dependencies, layer status, and evidence
owners. The inventory is projected through the AOT native boundary and loaded
as =mrr_gerbil::load_iso_profile=. It describes evidence state; it cannot widen
the parser grammar or turn partial support into a conformance claim.

The active Rust boundary is =mrr-frontends=. It consumes a validated
parser-owned Rowan CST, constructs only a private semantic projection, and
lowers the admitted Graph-Relational slice directly to =MetaQueryIr=. Shapes
that have parser syntax but no MRR lowering fail closed by exact parser-owned
kind. No rejected shape publishes partial IR and there is no legacy parser
fallback.

* Profile semantics

The profile uses four evidence states:

- =partial=: an executable slice exists at that layer;
- =not-implemented=: the inventory names the layer but MRR publishes no value;
- =not-applicable=: the feature has no value at that layer;
- =implemented=: reserved for evidence backed by adjudicated licensed clauses.

Because licensed-clause adjudication remains pending, no layer may claim
=implemented=. =gql-query-language-frontend-v1= is the selected bounded
frontend. =gql-iso-audit-v1= inventories the whole standard without claiming an
implementation. =gql-iso-language-frontend-v1= is a target profile, not the
current release claim.

Syntax support and MRR semantic admission are separate facts. Gerbil Parser may
accept a complete ISO construct while MRR intentionally rejects it because
=MetaQueryIr= has no owned representation. Such a rejection is positive
boundary evidence, not a reason to reintroduce a Rust GQL framework.

* Current executable surface

The parser-owned frontend currently exercises the bounded query surface in
=crates/mrr-frontends/tests/unit/contracts.rs=. Its positive contracts cover:

- identifiers, parameters, Unicode strings, numeric and structured literals;
- node and edge patterns, multiple paths, labels, properties, and direction;
- =MATCH=, =WHERE=/=FILTER=, projection, aliases, distinct and wildcard results;
- arithmetic, Boolean and truth predicates, aggregate functions, grouping,
  ordering, offset, and limit;
- stable canonical =MetaQueryIr= and parser-authority receipts.

The same owner contains negative contracts for malformed parser input,
unsupported match/path modes, operators not represented by =MetaQueryIr=,
mutation, and complete query pipelines that cannot be admitted atomically.
These cases must return typed failure without replaying a second parser or
publishing a partial query.

Catalog management, graph mutation, procedures, session control, optional
matching, quantified paths, and the remainder of query composition stay in the
inventory but do not have a public Rust domain model. Their MRR semantic layers
remain =not-implemented= until a concrete =MetaQueryIr= boundary and executable
acceptance evidence exist.

* Publication contract

A parser result is publishable only when all of the following hold:

1. Native runtime status and payload schema are accepted.
2. Language, grammar version, grammar digest, and source digest match the
   requested parser authority.
3. Node, field, and token events are balanced; byte ranges are continuous and
   replay the exact UTF-8 source.
4. Every semantic shape is owned by the private frontend projection.
5. Lowering produces one complete, normalized =MetaQueryIr=.

Failure of any premise publishes neither a CST claimed as admitted nor a query
IR. External implementations may supply differential examples, but they are
never normative dependencies or fallback parsers.

= ISO GQL Profile Admission

For parser artifact $a$, profile receipt $p$, and private lowering $L$,

$ "publish"(L(a), p) "iff" "authority-valid"(a, p) and "total-owned"(L, a) $

$ not "authority-valid"(a, p) or not "total-owned"(L, a)
  => "cst" = "none" and "ir" = "none" $

* Performance and observability

Performance scenarios must execute the real parser-owned AOT path and retain
their declared sample count. A slow 100-sample scenario is an algorithm or
boundary problem; reducing the corpus is not an optimization.

=GERBIL_BUILD_VERBOSE=1= (or a higher native level when debugging) controls the
first-party Gerbil build trace. POO Flow observations identify owned build
phases. Cargo adapters must preserve those semantics and expose enough nested
stage information to distinguish Gerbil closure generation, Gambit C emission,
native C compilation, archive creation, and Rust linking. A heartbeat without
the active native substage is not adequate observability.

* Evidence owners

- Profile schema and inventory: =scheme/grammar/gql-profile.ss=
- Native loading and validation: =crates/mrr-gerbil/tests/unit/contracts.rs=
- Parser-owned query admission: =crates/mrr-frontends/tests/unit/contracts.rs=
- Project boundary policy: =build-support/mrr-asp-rust-project-policy/tests/unit/=

Historical evidence for the removed Rust GQL stack remains available in Git
history. It is not an active owner and must not be restored as a compatibility
path.
