* Status

Accepted architecture.

* Decision

=mrr-relation= is the sole owner of language-neutral relation schemas and
facts.  It also owns =EntitySchema= so Property Graph node properties reuse the
same recursive =ValueSchema= and =RelationField= contracts rather than defining
a graph-only value system.  A relation schema binds a stable =RelationId= to a predicate, an ordered non-empty
set of uniquely named typed fields, nullability, and generic relation
constraints.  =ValueSchema= is recursive and parameterized: decimals retain
precision and scale, floats retain width, temporal values retain unit and
timezone policy, and lists and records retain their element shape.  Ordered fields
generalize the subject/object pair without turning graph vocabulary into core
authority: a binary relation uses subject and object fields, while rule and
query relations may use any validated arity.

A fact cannot be constructed without =RelationContext=.  The context keeps five
orthogonal claims explicit:

- semantic =GenerationId=;
- authority owned by an entity, rule, or rule pack;
- source or derivation provenance;
- complete, partial, or unknown evidence coverage;
- valid or explicitly invalidated fact state.

These claims are typed data, not strings and not frontend metadata.  GQL,
Cypher, Gerbil, and Ascent may produce or consume the contract, but none owns or
redefines it.  There is no arity-only constructor and no context-free fact
constructor.  Source provenance must name the same entity as entity authority;
rule and rule-pack authority require derivation provenance.  Bundle admission
revalidates schemas and contexts after decoding, so serde cannot bypass the
constructors.

* Shared-domain acceptance

The executable relation tests instantiate software =calls=, knowledge
=supports=, and workflow =permits= facts through the same =RelationSchema=,
=Fact=, and =RelationContext= types.  Domain changes do not add core enums or
alternate validation paths.

= RFC 0005: Typed Relation Core

Let $S(r) = ((t_1,n_1), dots, (t_n,n_n), C)$ be the ordered parameterized field
schemas, nullability flags, and relation constraints admitted for relation $r$.
A fact $f = (r, (v_1, dots, v_m), c)$ is shape-valid exactly when

$ m = n and forall i in {1, dots, n}: "valid"(v_i,t_i,n_i). $

The context $c = (g, a, p, e, v)$ keeps generation, authority, provenance,
evidence completeness, and validity distinct.  No projection may infer one of
these components from another.  In addition, $"coherent"(a,p)$ is required and
a fact may not invalidate itself.
#+end_src

* Verification

The focused suite rejects wrong arity, wrong value type, non-canonical decimal
and temporal values, nullability violations, invalid constraint references,
incoherent authority/provenance, self-invalidation, empty fields, duplicate
field names, and wrong relation identity.  It also proves that the three MVP
domains use one core.  Bundle admission revalidates decoded schemas, and
workspace compilation ensures every existing consumer uses the mandatory
constructor and typed accessors rather than a legacy public-field path.
