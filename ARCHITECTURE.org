* Ownership boundary

=gerbil-parser= is the sole GQL concrete-syntax owner. It produces a
source-bound, lossless parse artifact through the linked Gerbil AOT runtime.
=mrr-gerbil= owns the native ABI and Rowan projection. =mrr-frontends= lowers
the admitted parser-owned CST directly into =mrr-query::MetaQueryIr=.

There is no Rust GQL lexer, parser, public AST, catalog, semantic analyzer, IR,
compiler, facade, command subprocess, or compatibility path in this workspace.
Unsupported parser syntax and semantics fail closed with typed errors. An
accepted CST must reproduce the complete source before semantic lowering.

* Reasoning boundary

The =mrr-*= crates own language-neutral identity, relation, query, logic,
bundle, lineage, revision, transition, and conformance contracts. Scheme ASCENT
may propose bounded fixed-point candidates, but only the public
=meta-relational-reasoning= facade can admit and materialize a complete result.
Compiled Scheme inference is invoked through the native boundary.  Caller- or
model-supplied Scheme source is not evaluated on the Rust query path; POO Flow
retains its declarative and Temporal semantic ownership.

The complete ownership decision is recorded in
=docs/architecture/0001-mrr-workspace-ownership.org=. Parser authority and ISO
profile evidence are recorded in RFC 0002 and RFC 0024.

* Agentic AI Context System

MRR owns the Context domain and source admission. =mrr-agentic-ai-context=
selects explicit facts and their declared dependency closure, tracks revision
impact, materializes ordered segments, and checks token-prefix reuse eligibility.
The facade binds this view to an existing admitted bundle and catalog query.
The [[file:docs/architecture/agentic-ai-context.org][Context authority]] records premises,
the independent =MRR.AgenticAIContext= proof project, and runtime boundaries.
=lean-poo= remains pure composition mathematics; =mrr-data= owns generic
persistence through downstream adapters.

RFC 0035 and RFC 0036 propose the next boundary: typed Content authority,
obligations and compliance receipts, followed by authority-aware Context
projection and invalidation.  The present Context implementation does not yet
admit those contract or evidence classes, and its token-prefix eligibility is
not an observed serving-cache hit.  POO Flow remains the policy and Temporal
semantic owner; the MRR production runtime must enforce a checked decision at
an effect boundary.  =mrr-data= remains a physical downstream adapter.
[[file:docs/architecture/0037-meta-relational-impact.org][RFC 0037]] proposes a
typed meta-relational Impact step between reverse reachability and the
semantic/action verdict.  It preserves POO Flow's separate structural,
Temporal, trajectory, and causal claim levels.
[[file:docs/architecture/0038-context-session-lifecycle.org][RFC 0038]]
proposes a Context Session semantic head for one shared POO Flow Session ID.
It binds turns and existing Query/Context receipts while POO Flow and the
runtime retain policy, scheduling, persistence and effects.  No Session-head
API is implemented in this checkout.

The facade feature =agentic-ai-context= enables the Context domain;
=agentic-ai-context-tokens= additionally enables external-tokenizer and reuse
contracts. Both are off by default. Storage and model implementations remain
downstream adapters, and no Context feature introduces a dependency on MRR Data.

= Meta-Relational Reasoning Architecture

Let $"parse" : "Source" -> "CST"$ be the parser-owned AOT operation and
$"lower" : "CST" -> "MetaQueryIr"$ be the only GQL semantic projection in MRR.
The frontend requires $"bytes"("parse"(s)) = s$ and publishes no query when
parsing, semantic lowering, or admission fails.

The reasoning predicate $"BundleValid"(R, F_0, P, T)$ is defined by the
language-neutral MRR contracts and detailed in RFC 0001.
#+end_src
