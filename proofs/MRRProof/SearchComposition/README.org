* Mathematical semantics

Let A be the primary candidate set and B the auxiliary candidate set. Sets are
predicates over an arbitrary Candidate type.

| Mode | Returned set | Completeness requirements |
|------+--------------+---------------------------|
| Single | A | Partial results are allowed; complete/truncated status is retained. |
| RankJoin | A | The primary branch must be complete. Auxiliary ranking may be partial and cannot remove members of A. |
| Intersect | A intersection B | Every branch must be complete and untruncated. Only then can an empty result certify the absence of common hits. |

Sequential composition is g composed with f, with associativity proved.
Parallel composition maps x to (f(x), g(x)). C3 role linearization and C4
precedence are separate inputs. C4 order does not create retrieval or causal
edges.

MRR directly consumes LeanPoo's C3 =ParentDerivations= and
=GraphCertificate.derivations=, together with C4 ancestry coverage, output length
bounds, preservation of ancestor-local constraints, and precedence monotonicity
in descendants. Executable checks also exercise a C3 graph with a shared ancestor
and queries over a verified C4 ancestry index.

The actual POO projection supplies edges E. Influence requires an E-path of
length d with d <= maxDepth. Parallel branches without connecting edges cannot
produce cross-branch influence.

* State machine and safety theorems

A state contains its phase, current binding, observed binding, completeness of
both branches, inferred status, and candidate output. A binding consists of
(workspace scope, source, resident view, composition ABI, generation).

The main transition sequence is =read -> merge -> ready -> published=, with
additional revise, restart, and stay actions. A revision retires old results
before or after publication, clears inferred status, and requires fresh
observations before publication can resume.

=step_preserves_valid= proves that each legal action preserves the invariant.
=reachable_valid= extends this result by induction over legal traces. Every
reachable published state therefore satisfies:

1. Its observed binding equals its current binding; stale generations and foreign sources cannot publish.
2. Both Intersect branches are complete and untruncated.
3. Inference evidence has been admitted, and the returned set exactly matches the selected mode's semantics.
4. A published empty complete intersection implies that no candidate belongs to both branches.

* Lean, Quint, and execution correspondence

| Model concept | Lean | Quint | Execution owner |
|---------------+------+-------+-----------------|
| Three candidate-set semantics | Search.truth | truth | Data search_candidates.rs |
| Completeness admission | truthReady | truthValid | Data validate_branches |
| Exact snapshot binding | Binding, observed = current | current, observed, bindingValid | DataSearchSourceBinding |
| Read, merge, revision, and publication | Step, Reachable | read/merge/revise/restart/publish/stay | ASP generation admission and search composition |
| Influence paths and distances | Path, influence | Outside this finite publication model | MRR POO projection and factor evaluator |
| C3/C4 | GraphCertificate, VerifiedOrder | Algorithms are not reimplemented | LeanPoo / POO Flow |

Positive Quint cases cover Single, RankJoin, Intersect, partial Single, and a
non-overlapping complete intersection. Required counterexamples cover generation
reuse, scope/source/resident/ABI substitution, incomplete primary or secondary
truth branches, skipped inference, a false empty intersection, and RankJoin
filtering the primary set. Positive exhaustive checks require an empty work
queue. Negative controls require TLC to report an actual invariant violation
and counterexample.

* Exhaustive Lean replay coverage

Lean independently enumerates the successor closure of each positive finite
fixture. Every exported state passes an executable admission check;
=Replay.acceptance_sound= proves that acceptance implies the original
=Protocol.valid= invariant. The exporter also checks that its state set is
closed under every finite successor action.

TLC then exhaustively checks =allStatesReplayed=: every reachable Quint state
must belong to the exact Lean replay set and satisfy the original safety
invariant. The gate requires equal distinct-state counts, no duplicate replay
states, and an exhausted TLC queue. An omitted published state must produce an
actual invariant counterexample. This establishes finite state coverage rather
than relying on sample traces or inferred checker counts.

The five positive fixtures currently contain nine states each, for 45 state
replays across fixtures. The replay specification fixes the four non-generation
binding fields to zero and checks the declared generation interleavings; this
does not expand the finite scope to arbitrary provider state.

* Actual ASP execution witnesses

ASP emits a separate =agent.semantic-protocols.search-execution-witness=
Version 1 diagnostic. Its =compositionReceipt= embeds the existing Version 1
receipt without changing that receipt's contract. Bounded diagnostics set
=complete=false= and omit the witness when their inventory cannot be retained.
Lean rejects incomplete witnesses.

=ExecutionModel.lean= proves that owner composition has the original =Search.truth=
membership semantics. =ExecutionChecks.lean= independently checks actual leaf
owner sets, common source/generation bindings, Data aggregation, POO fan-in and
shortest paths, causal observations, and the complete MRR influence inventory.
The current qualification supports Single with one leaf and Intersect/RankJoin
with two leaves. It checks set membership rather than ranking order.

Run from the repository root with absolute paths to the actual ASP output and
its independent schema:

#+begin_src sh
./.devenv/devenv-profile-exec just search-execution WITNESSES SCHEMA
#+end_src

The captured environment needs =jsonschema= for format validation; the Python
proof project declares it through the =execution= extra. Python orchestrates
schema validation and CLI exits; Lean owns semantic checking. The gate retains
six rejected mutations: stale generation, a foreign merged owner, a missing
POO path, missing influences, an incomplete witness, and a foreign causal parent.
A direct Lean-only entry is =just search-execution-proof WITNESSES=.

Local evidence is under =.ci/search-model/execution/=. The qualification receipt
binds the actual witness, schema, checker, and owner-membership model by SHA-256.
This is differential checking of emitted evidence. It does not authenticate
candidate IDs against owner bytes, establish Rust/Scheme source refinement, or
extend the finite Quint coverage claim.

* Actual POO role graph certificates

A separate =search-order-witness= Version 1 diagnostic retains actual
=object-supers= parent graphs and =compute-precedence-list!= outputs from the
same POO stage objects that produce the admitted factor inventory. Current POO
objects use Gerbil C4 at runtime. The evidence identifies that algorithm
explicitly; it does not describe the runtime as C3.

=OrderChecks.lean= matches the entire embedded composition receipt against the
execution witness, including source/generation/composition/DAG identities. It
then certifies the actual graph using LeanPoo C3 and C4 and compares both orders
with each retained runtime order. A C3/C4 disagreement fails qualification;
these checks do not change POO's runtime algorithm or schedule provider work.
The graph aliases are packet-local and acquire meaning only within this binding.

=PlanOrders.lean= retains dependent graph certificates with binding, composition
and DAG identities, and proves stale-generation and foreign-DAG rejection.
These are graph certificates plus executable identity correspondence. Source
admission, digest authenticity and full compiler refinement remain separate.
The existing execution/composition Version 1 schemas remain unchanged.

Python only validates the independent schema and orchestrates CLI controls.

* Actual candidate correspondence

=CandidateChecks.lean= matches a separate Version 1 Data candidate witness to
the complete actual execution receipt. It checks the exact physical owner union,
unique owner/candidate inventory and all branch/merged observations. The
=search-candidates= recipe validates the schema, runs Lean and requires seven
corrupted controls to fail. Python performs schema/process orchestration only.

Data Rust owns canonical UTF-8 byte encoding and identity derivation. ASP calls
Data admission before inference. Lean does not authenticate physical bytes,
prove hash collision resistance or trust a coherent substitution of both logs.
Actual public receipts and focused Rust evidence are under
=.ci/search-model/candidates/=. Existing C3/C4 and execution gates also pass over
the regenerated public evidence. This is local qualification with unpublished
bindings; durable reflection projection and published source convergence remain
separate gates.
