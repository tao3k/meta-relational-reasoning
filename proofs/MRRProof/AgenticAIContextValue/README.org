#+title: Agentic AI Context Value and element equality proof
#+options: toc:nil

* Actual Rust Value equality source proof

This scope extracts the production =equal_value_lists=, =equal_value_records=,
=equal_record_fields=, recursive =Value::eq= and derived =Fact::eq= from
=mrr-relation=, plus actual =AgenticAiContextElement::eq= and
=revision_elements_differ= from =mrr-agentic-ai-context=. Charon and
Aeneas versions match the Context Rust source proof. Generated files are checked
byte for byte; only the documented ASCII conversion is applied.

It is separate from =AgenticAIContextRust= because the generated discriminant
instances share global names even when Aeneas namespaces differ. This is not a
hand-written replacement implementation or a proof of complete revision assembly.

** Admitted interface

There are no external type obligations. Two generated external functions are
admitted: exact String equality and primitive Bool inequality, both computable
value models. The extracted core Option equality also uses the logical Option
discriminant model (None = 0, Some = 1). Aeneas's
existing array, byte, Vec, Slice and machine-integer value models remain trusted
interfaces. No Rust unsafe storage or allocation implementation is verified.
Generated external-template axioms are never imported.

** Current laws

The audit requires 53 declarations, including the original 35 Value laws and
18 identity, context, Fact, element and classification composition laws. Source laws cover
all twelve atomic variants, constructor mismatches, key short circuit, list/record
delegation, unequal lengths, empty inputs, exhausted loops and an already-false
loop accumulator. These quantify over all inputs in their stated domains.
=native_atomic_value_equality_exact= combines all atomic branches into exact
logical equality against any right-hand value, with no comparison oracle premise.
Its classical DecidableEq instance is proof-only and supplies no Rust implementation.

=ValueLoops.lean= proves totality and exact suffix equality for both actual index
loops, including checked reads and increments, and exact whole-slice equality
for their length-check wrappers. =ValueRecursive.lean= discharges all indexed
child premises by the generated eight-motive nested =Value.rec= recursor.
=native_value_equality_total= establishes that actual Rust equality returns
~.ok (decide (left = right))~ for every pair of recursive Values, including
nonempty lists and ordered records with duplicate keys. It has no child-equality
or final comparison oracle premise. The key-first record comparator is exact as
well. This is logical termination of the extracted pure function within the
admitted library interfaces, not a native stack-capacity guarantee.

=FactEquality.lean= proves all Fact fields (id, relation, recursive values and
context), all context fields, ordered dependencies and actual element equality.
It then proves imported core Option equality and the actual production
=revision_elements_differ= predicate: it returns exact inequality of optional
elements, including added/removed elements, without any equality premise.
The caller retains its original global-change short circuit before map lookup.

Exact changed-set construction from the actual source maps and complete revision
assembly remain separate gates. This predicate theorem does not prove either.
[[file:../../quint/README.org][Quint lifecycle checking]] and Lean publication proofs continue to guard scheduling
and publication; they do not discharge these Rust equality obligations.
