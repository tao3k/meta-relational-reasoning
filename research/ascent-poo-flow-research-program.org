#+title: MRR Research Program for Ascent and POO Flow
#+date: 2026-09-25
#+status: research proposal

* Research question and ownership

How can Ascent's fixed-point and BYODS machinery support dynamic, explainable,
and independently admitted reasoning for Agent systems?  MRR owns relation and
rule semantics, identities, generations, lineage, transitions, and admission.
Ascent and future physical evaluators produce candidates.  POO Flow composes
policy, capability, resource strategy, and runtime handoff.  The corresponding
[[https://github.com/tao3k/poo-flow/blob/main/docs/10-19-design/10.06-poo-module-system/ascent-mrr-research-program.org][POO Flow research program]]
owns the first control-plane slice.  This note does not change the accepted
[[file:../docs/architecture/0003-mrr-ascent-evaluation.org][bounded Ascent RFC]] or
[[file:../docs/architecture/0025-poo-flow-mrr-agent-assurance.org][assurance boundary]].

The first experiment maps a bounded binary relation query to POO prototypes,
C4 inheritance, persistent sets, and an indexed right-hand join.  POO Flow
exposes an explicit frontier step and a demanded full closure for the selected
positive binary transitive rule.  Its focused fixture checks multiple
derivations, a cycle, an empty final frontier, source withdrawal, and the
complete 12-pair set.  A paired MRR/Ascent fixture checks the same five-edge
graph.  This is set-level parity for one bounded rule, not general Datalog,
shortest-distance lattice parity, support selection, or an admissible MRR
receipt.  The next cross-repository step is to bind full candidate sets to
exact source generations and exercise the control and evidence path.  A
Scheme experiment remains an independent candidate and cannot publish MRR
facts.

* Current baseline and gaps

The accepted evaluator handles exactly one selected two-rule transitive
closure shape over a validated bundle.  It checks finite input and pair bounds
before Ascent, reconstructs deterministic shortest witnesses, and emits a
generation-bound V1 =ClosureReceipt=.  The facade binds this runtime evaluation
to the exact admitted =ReasoningBundleId= without changing the V1 receipt
schema or digest.  Admission checks that Bundle identity even when two bundles
reuse the same input =FactId=s, and
checks the requested generation even for an empty closure.  It then requires
complete output, caller-assigned identities, lineage validity, and transition
validity.  Binding a source owner's semantic snapshot to the caller-supplied
generation remains a separate obligation.
[[file:ascent-mvp-capability.org][The MVP capability note]] records that parallel
evaluation, BYODS, and deletion maintenance are not used in that slice; this
does not mean upstream Ascent lacks parallel or BYODS support.  MRR transition
can represent retractions, but evaluator maintenance across retractions has not
been established.  [[file:why-provenance.org][WHY provenance notes]] defer
recursive equations, multiplicities, semiring annotations, and trust-valued
provenance; current WHY projects an admitted finite explanation graph.

The [[file:../docs/architecture/0022-mrr-performance-baseline.org][performance baseline]]
uses independent self edges for Ascent closure.  It is a useful reproducible
baseline but does not measure recursive multi-support graphs or update-heavy
workloads.

The POO experiment deliberately uses the native library fixed point for
recursive *function-slot binding*.  MRR's Ascent contract evaluates a least
*relation* closure and then reconstructs shortest support.  The two meanings
must be compared through observable result and receipt fields, not equated by
their shared name.  Gerbil-POO's table =.join= is a map union; it is not an
Ascent rule-body relational join.  The focused MRR fixture test
=derives_deterministic_shortest_lineage_candidates_from_a_validated_bundle=
passed.
The public =mrr-closure-tool= admitted three independently constructed
snapshots of that same diamond: four edges produced five candidates and
Ada-to-Cy =true=; removing Bob-to-Cy produced four candidates and =true=;
also removing Dan-to-Cy produced two candidates and =false=.  The POO
primitive fixture exercises native persistent source-set composition; its
hand-written graph walk was removed because it duplicated Ascent rather than
reusing a standard-library closure operation.  A separate POO relation
expression fixture checks bounded joins and explicit frontier steps.  The
paired =cyclic_frontier_fixture_matches_the_poo_relation_pairs= test checks
the same graph through MRR/Ascent.  The same three MRR
candidate sets are asserted by
=source_snapshots_match_expected_ascent_closure= in the MRR Ascent tests;
the focused Ascent, facade, and conformance run passes 39 tests across eight
suites.  These CLI calls are fresh snapshots, not a test of MRR's
transition-based retraction or POO candidate admission.
The differential fixture also withdraws whichever shortest Ada-to-Cy witness
the evaluator selected, checks that the other branch becomes its support at a
new requested generation, and then removes that branch.  The final result
contains no Ada-to-Cy candidate.  The old receipt remains immutable and the
new receipts have distinct digests.  This is from-scratch support reselection
across separately admitted snapshots; incremental deletion maintenance and a
validated source-snapshot-to-generation binding remain open.
The inspected POO library has no general relational join, least-closure
evaluator, or shortest-support operation.  The bounded POO table expression
composes binary pairs from a =UIntTrieSet= source through a private adjacency
index.  Its =delta-step= returns an incremental set and an accumulated set
using the library's =Table .merge= and =Set .union=.  The declared V19 =Set
.diff= method omits operands in its forwarding call, so the experiment uses
=Table .merge= directly.  A separate demanded closure projection uses the
library's =until= combinator and private bounded membership storage; it
publishes canonical pairs and optional persistent-set materialization.  The
20-node chain fixture checks all 190 reachable pairs, with local optimized
p95 of 119us over 20 standard samples.  POO does not currently implement
MRR's canonical =FactId= tie ordering or produce an admissible support receipt.

* Agent problem and value hypothesis

Current Agent workflows often make several decisions from retrieved text,
tool output, and model summaries.  Their failure is not only a wrong final
answer: a stale source, missing supporting path, unobserved contradiction, or
revoked capability can lead to an unjustified next action.  MRR's research
value is to turn relevant source-bound observations into typed, generation-bound
derivations with explicit coverage, invalidation, and explanation.  Ascent
supplies efficient candidate computation; POO Flow supplies the context and
decision boundary.  Search, inference, probabilistic judgment, authorization,
and effect remain distinguishable in every trace.

Jev is a concrete decision-model case.  The
[[https://docs.typesafe.ai/introduction][official TypeSafe documentation]]
defines Choice, Score, and Noul answers over supplied state and typed questions.
The model is useful for routing, ranking, or deciding what evidence to seek
next.  Its probability is a judgment about the supplied state, not a source
fact, proof of a derivation, or permission to act.  Research questions include:

- Which exact source revisions, selectors, admitted derivations, and coverage
  claims must be projected into a compact state before a model can judge?
- Can a model choose among only valid, capability-allowed options, while MRR
  explains why each option is supported or ruled out?
- When a source or support is withdrawn, which prior judgments and downstream
  decisions require re-evaluation, and can this be computed incrementally?
- Does adding MRR derivations improve independent task outcomes and calibrated
  abstention enough to justify its cost over retrieval plus a decision model?

The same questions apply to generative LLMs, human reviewers, and other
decision models.  Do not encode Jev-specific output fields as MRR fact
semantics.  Bind model version, question criteria, supplied-state digest,
output distribution, and observation time in an external proposal/receipt
when an experiment needs them; source ownership and MRR admission remain
separate.

** Scenario fixtures

| Scenario | Inputs and MRR task | Decisive failure fixture |
|----------+---------------------+--------------------------|
| coding Agent patch planning | exact code snapshot, call/dependency facts, changed API; derive transitive affected tests and explain supports | delete or revise one caller and verify affected-set and witness invalidation |
| incident triage | versioned topology, log observations, causal hypotheses; derive bounded influence and competing support | stale log or contradictory observation must not silently become a unique root cause |
| research Agent | cited passages, revisions, claim links; derive support/contradiction and coverage gaps | one source retraction leaves an alternative support or forces abstention |

Build task-level oracles from frozen fixtures and independent human/source
adjudication.  Compare generative-only, retrieval plus judgment, and
retrieval plus MRR plus judgment/control under the same action set and budget.
Measure source/impact recall, unsupported claims and actions, explanation
fidelity, calibration and abstention, end-to-end success, latency, and cost.
TypeSafe's [[https://typesafe.ai/blog/introducing-system-one-models-and-jev][launch claims]]
motivate a hypothesis; they are not our benchmark receipts or correctness
oracle.

* Priority research questions

** 1. Exact maintenance under insertion and retraction

Compare [[https://ojs.aaai.org/index.php/AAAI/article/view/11554][DRed,
Backward/Forward, and Counting hybrids]] with
[[https://arxiv.org/abs/2203.16684][DBSP-style incrementalization]] for the
MRR rule class actually admitted.  The invariant is:

#+begin_example
after every admitted source delta at generation g:
  incremental_result(g) = from_scratch_result(g)
#+end_example

Equality includes the derived fact set, all required supports, deterministic
witness selection, and the admitted generation/identity bindings.  Receipt
digests may differ across distinct physical plans only if a separately
specified canonical semantic receipt remains identical.  Source deletion,
revocation, cancellation, and a stale generation must never materialize a
prefix of a result.  The experiment must include diamonds, cycles, multiple
independent supports, and deletion of one support that leaves another valid.

** 2. Finite recursive provenance

[[https://www.cs.ucdavis.edu/~green/papers/pods07.pdf][Provenance semirings]]
offer a general annotation algebra, but
[[https://proceedings.kr.org/2022/10/kr2022-0010-bourgaux-et-al.pdf][recursive
Datalog provenance]] has several non-equivalent semantics and potentially
infinitely many derivation trees.  Choose the intended semantics before adding
a public type.  Study finite cyclic equations, bounded minimal witnesses, and
support invalidation separately.  Keep an uncertainty or trust annotation
distinct from source authority and admission: a score does not turn a proposal
into an authoritative fact.

** 3. Rule and provider contracts

[[https://www.cl.cam.ac.uk/~nk480/datafun.pdf][Datafun]] motivates typed
monotonicity and termination checks.  [[https://kmicinski.com/assets/byods.pdf][BYODS]]
permits custom relation representations, whose delta/total behavior must
preserve the rule semantics.  Specify an admitted rule subset and a provider
contract before comparing physical plans.  Test joins, index choices,
parallelism, and custom storage against an independent bounded oracle and the
current Ascent adapter.  POO Flow may choose a profile; MRR owns the semantic
equivalence and receipt requirements.

** 4. Equality and constraints as separate extensions

[[https://effect.systems/doc/pldi-2023-egglog/paper.pdf][egglog]] already
combines Datalog with equality saturation.  First test whether its term
rewrites can optimize rule or plan candidates while retaining a checkable
equivalence witness.  [[https://arxiv.org/abs/2009.08361][Formulog]] shows a
Datalog/SMT path for constraint-heavy analyses.  Neither extension should be
silently folded into the current two-rule closure contract.

* First experiment and exit criteria

1. Freeze one validated rule pack, source-generation sequence, and canonical
   semantic-result format.  Use current Ascent from-scratch evaluation as the
   baseline, not as its own sole oracle.
2. Run inserts, single-support deletions, multi-support deletions, cycles,
   source revision changes, and budget/cancellation failures.  After each
   delta compare incremental proposals with independent full recomputation.
3. Check exact derived pairs, surviving support sets, deterministic witness
   order, complete/partial status, and MRR lineage/transition admission.
4. Benchmark cold, warm, sparse-delta, and high-fanout cases on exact
   revisions; report time, memory, and evidence size separately.  Preserve
   failures as typed counterexamples rather than counting an exit code as
   semantic success.

The first milestone is a cross-repository end-to-end control/evidence
demonstration plus this executable differential fixture.  It does not claim
general recursive provenance, arbitrary Datalog, BYODS speedup, or runtime
release readiness.
